# M9 调研总览

三项需求的调研结论汇总。分册各一篇，本文件只做索引、口径固化与实施顺序。

| 需求 | 分册 | 结论 |
| --- | --- | --- |
| 流光动态背景 | `M9-android-ambient-background.md`（参考）、`M9-win-ambient-background.md`（桌面方案） | QPainter 自绘五色加权光场，50fps，形态对齐手机版 |
| 播放统计 | `M9-android-playback-stats.md`（参考口径）、`M9-win-playback-stats.md`（桌面方案） | 独立 `play_stats.json`，听满 30 秒或播完 +1，墙钟计时 |
| 音质与码率标签 | `M9-quality-bitrate-label.md` | 播放条中间组右侧加可压缩标签，三源数据可得性已核 |

## 口径固化

以下五条来自用户在调研过程中的明确指示，实施时不得改动。

1. **播放时长 = 这首歌累计被收听的时长**，不是最近一次播放的时间点，也不是歌曲本身时长。暂停、缓冲、加载中、切歌空档一律不计。跨会话累加。seek 跳过的部分不算。
2. **统计页不显示「最近播放」列**。`last_played_at` 只用于默认排序的次级键，不上界面。
4. **「日d时:分:秒」是时长展示格式**，不是按天分桶的统计维度。v1 不做日/周/月/年切换。
5. **流光背景一直流动**，不随播放状态启停；形态是**连续弥散光场**（五色加权融合），不是五个可数光球；配色为**单色系不同明度**。
6. **播放统计入口在设置页**，点开后是独立页面，表格列把「作者」「歌曲时长」换成「播放时长」「播放次数」。
5. **音质标签窄窗口下只显示档位名，不出省略号**。标签只有两种完整形态：「无损 FLAC · 1411 kbps」与「无损 FLAC」，按可用宽度整态切换。实测切换点为窗口 912px。

## 三项的相互独立性

三者互不依赖，可独立实施、独立发布：

- 播放统计新增独立数据文件与页面，不碰主题与绘制。
- 音质标签改 `PlayerBar` 布局与 `_SongContext` 字段，与另两项无交集。

唯一的重叠点在 `settings_page.py`：统计入口与将来可能的外观开关同在设置页，但分属不同分组，不冲突。

## 实施顺序建议

按「风险从低到高、依赖从少到多」排：

1. **音质与码率标签**。改动最小，只动 `player_bar.py` 与三个 `_resolve_*_context`，不动数据层，可先验证。
2. **播放统计**。新增数据文件与页面，逻辑独立，但需要处理计时口径与 flush 时机，测试面较大。

若时间只够做一项，做音质标签；它是最小可交付且用户感知明确的一项。

## 已知未决项

| 项 | 影响 | 建议 |
| --- | --- | --- |
| 网易云播放接口的 `br` 字段是否稳定返回 | 决定网易云能否显示码率 | 实现阶段抓一次真实响应确认；不确认也能上线，只显示档位名 |
| `QRhiWidget` 的下限（Qt 6.7）与当前 `PySide6>=6.6` 冲突 | 若将来要走 GPU 路线需抬下限 | 当前 CPU 方案不触发，暂不处理 |
| 音质标签窄窗口形态 | 两态整态切换，无省略号 | 已实测切换点 912px，无未决项 |

## 与 Android 端的差异汇总

桌面端不照搬的部分，以及理由。

| 项 | Android | Windows 方案 | 理由 |
| --- | --- | --- | --- |
| 统计存储 | Room + 分片计数器 + 幂等 eventId | 单 JSON + 15 秒 flush | 单进程 Python 无并发写，分片与幂等键是过度设计 |
| 统计维度 | 日/周/月/年 + bucket 表 | 只做全量累计 | 用户明确只要求累计次数与累计时长 |
